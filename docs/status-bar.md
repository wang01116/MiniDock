# 顶部状态栏只在真正全屏时隐藏（本地 v7）

此页保留 v7 的策略说明。v8 输入法修复见 [ime-indicator.md](ime-indicator.md)，v9 顶部重复占位修复及最新检查数量见 [top-gap.md](top-gap.md)。

浏览器、播放器和游戏普通打开或窗口最大化时，顶部状态栏保持显示。前台视频/游戏窗口进入真正全屏后才隐藏，并释放本状态栏的顶部占位；退出全屏、切换到普通窗口后恢复显示及占位。判定独立于底部 Dock 的游戏模式。

## 本轮修正

之前有两条路径导致不符合要求的隐藏：

- 窗口最大化且标题命中视频网站名称时就被当作视频内容，即使没有全屏播放。
- 原“智能隐藏”在普通窗口下把状态栏移到屏幕顶部之外，鼠标触顶才显示。本机配置中该开关开启，能解释普通打开浏览器也看不到状态栏的现象；未对用户每次操作录制调用轨迹。

v7 去掉视频网站标题匹配和鼠标触边收起逻辑。全屏须覆盖状态栏所在的整个显示器，并去掉普通窗口标题栏/可调整边框。仍带正常窗口边框的最大化窗口，即使系统任务栏自动隐藏后覆盖整个显示器，也不算全屏。

## 设置及兼容

“设置 → 状态栏设置”和右键菜单改为“全屏视频/游戏时隐藏”，默认开启。关闭后，全屏时也保留状态栏。

新配置键为 `[Settings] SbFullscreenHide=1/0`，复用原配置结构中的一个整数，不扩大配置结构。旧 `SbAutoHide` 键不再读取：旧值为 0 或 1，都不会重新开启触边收起；没有新键时默认开启全屏隐藏。窗口/分组、托盘名单和图标配置继续沿用。不会修改开机自启任务。

## 识别范围

- 浏览器全屏不依赖视频网站名称，支持未知站点的真正全屏视频。识别的是浏览器原生窗口全屏状态，不读取网页 DOM 或视频播放状态，因此浏览器 F11 全屏普通网页也会隐藏。这与窗口右上角“最大化”不同。
- 独立播放器按已有程序名单识别，只有真正全屏才触发，普通播放及最大化均显示状态栏。
- 游戏使用现有游戏名单、常见程序/引擎类及独占 Direct3D 信息；名单中的游戏也必须真正全屏才触发。无边框覆盖整个显示器的游戏属于全屏。
- 只检查本显示器的前台窗口，排除最小化、不可见、cloaked、工具覆盖层和 Shell 窗口。其他显示器上的全屏内容不隐藏本屏状态栏。
- 特殊播放器的全屏窗口若仍保留普通窗口边框，或使用名单外的宿主进程，仍需实际应用验证。

## 验证和资源

60 项状态栏检查通过，覆盖窗口样式、范围、网页标题、最大化/全屏、旧配置迁移、保存重载、开关切换、占位释放与恢复、绘制位置、多屏及鼠标离开顶部不再收起。加上窗口/分组 96 项、下载边界 16 项和动画 26 项，合计 **198 项通过**。

检查使用真实私有窗口，前台身份/窗口范围/样式由测试输入控制，AppBar API 用替身模拟，未改变用户桌面工作区。它验证本轮策略和状态转换，不等同于对所有真实浏览器、播放器和游戏的现场测试。

同 GCC 16.2.0、原版资源和构建参数下，v6 为 437,760 字节，v7 为 **436,736 字节**，减少 **1 KiB**。导入的 20 个系统 DLL 和 `.bss` 大小保持不变；未增加常驻线程、句柄或检测定时器，沿用原 250 ms 检查节拍。普通非全屏窗口会在读取应用身份和游戏名单之前返回，也不再扫描视频网站标题。未重新做整进程 CPU/内存长时间测量；此前数据仍是 v6 历史测量，不当作 v7 实测。
