# 托盘常驻窗口的通用身份恢复（本地 V14）

窗口标题会包含歌曲名、文档名、播放状态或未读数量。旧版重新绑定托盘应用时要求标题与配置完全一致，导致选中的主窗口仍在运行，Dock 却找不到它。本机网易云保存的歌名和实际歌名不同，旧代码的只读探针得到 `alive=0 bound=0`；修复后的通用代码在同一份旧配置和同一个实际窗口上得到 `alive=1 bound=1 valid=1`。

V14 不包含播放器名或专用窗口类的特判，分两层恢复：

1. 保存并校验 HWND、PID、进程创建时间，以及完整程序路径和窗口类。Dock 重启后，只要原进程和原窗口仍有效，就继续绑定这个窗口，标题可以变化或暂时为空。创建时间用于拒绝 PID 复用造成的过期身份。
2. 原窗口或进程失效后，再枚举同一路径、同一窗口类的窗口；保留活进程句柄时同时限制 PID。结合选中主窗口的边框、缩放/最小化能力和扩展样式筛选，排除附属窗口、子窗口、工具窗口和无标题占位窗口。标题仅作辅助提示；候选仍无法唯一确定时不按大小或枚举顺序盲选。

新身份信息写入原 `[TrayApps]` 配置。旧配置缺少这些字段仍可读取，在成功绑定后记录身份；不会要求用户逐个移除再添加。运行中窗口仍使用已保留的进程句柄，没有新增全局钩子、线程、轮询定时器或跨进程窗口属性，也没有改系统动画开关。原来的管理员运行和登录自启路径继续使用。

新增 `test-dynamic-tray.bat`，27 项检查使用真实隐藏私有窗口，只有用于测试的 EXE 身份查询被替换，不操作安装的播放器。覆盖两个任意播放器名、隐藏时改标题、保存后改标题、同类竞争窗口、相同标题的歧义、错误 PID/进程创建时间/窗口类、主窗口能力与登录框区分、错误安装路径、临时空标题、主窗口重建和辅助窗口排除。另保留原 274 项检查，合计 **301 项**。

V14 EXE 为 457,216 字节，比 V13 增加 1,536 字节；`.bss` 从 `0x163a00` 变为 `0x163b80`，增加 384 字节，DLL 导入列表相同。这些是静态构建差异，不等同于整进程长期 CPU/内存实测。未声称实测过所有播放器。

边界：若应用升级后改变主窗口类或窗口能力，或同时存在多个无法区分的主窗口，可能仍需用户重新选择。没有通用 Win32 属性可以完整表达第三方程序内部的“主窗口”语义；此处优先避免误操作辅助窗口。
