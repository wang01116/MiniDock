# 恢复动画末尾闪烁修复（本地 V10）

保留压缩飞入 Dock 的视觉效果，处理预览落地后切换为真实窗口时闪一下的问题。当前运行场景使用 MinStyle=0。

源码存在三个交接风险：预览先显示后填入内容；结束时先注销缩略图再销毁仍可见的普通弹出窗口，中间可能露出空白窗口；最后一帧才从窗口外框切换到 DWM 可见边界，随后撤掉覆盖层才激活应用，会造成边界跳动和额外的激活重绘。微软的 [GetWindowRect 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect) 说明窗口外框可能包含不可见的调整大小边框，与 DWM 可见范围不同。

V10 改为画面属性准备好后才显示预览，结束时先隐藏仍有画面的预览，再注销缩略图和销毁窗口，避免可见空壳。恢复落点在动画开始前计算，最后不再突然重定位：普通窗口参考保留缩略图尺寸修正常见的对称左右边框和底部边框，异常尺寸不做大幅猜测；普通最大化使用工作区，保留最大化标记的无边框全屏使用显示器范围。

真实窗口在覆盖层仍存在时恢复并激活，向其发送设置了 40 ms 超时的 WM_PAINT 请求，再保留两个 DWM 合成节拍后撤去预览。不会强制清空整个客户区或改变应用透明度、层级样式；没有截图缓存、附加线程或周期定时器。新增绘制请求和短暂保留覆盖层有交接耗时，不能把它理解成零成本。[DwmFlush](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmflush) 只同步调用方的合成提交，并不保证其他进程的全部 GPU 绘制都完成；特殊自绘边框、GPU 首帧和兼容回退路径仍需真实应用试用。

动画确定性检查从 26 增至 37 项，五组回归共 **254 项通过**。原 96 项窗口/分组、16 项下载、82 项状态栏和 23 项输入法检查保留。真实私有 Win32 窗口的 8 次最小化/恢复状态均正确，两次合成恢复时预览落点与实际 DWM 可见边界一致；这验证几何及交接协议，没有声称录制并排除了每种应用的一帧闪烁。原始记录见 tests/animation_handoff_results.json。

同 GCC 16.2.0、原版资源和构建参数，V9 为 437,248 字节，V10 为 **437,760 字节**，增加 **512 字节**。相对当前上游 main 的 432,640 字节增加 5,120 字节（5 KiB，约 1.18%）。系统 DLL 仍为 20 个，`.bss` 为 0x1638c0；没有新增常驻数据缓存或位图缓冲。此前 V9 的隔离 CPU/内存表保留为历史快照，不冒充本轮动画成本或 V10 实测。
