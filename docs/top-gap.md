# 顶部留白修复（本地 v9）

本轮保留 V8 输入法图标修复和此前功能，处理“顶部状态栏下方又有一条桌面空隙”的问题。

只读诊断发现：系统任务栏实际上位于顶部，矩形为 (0,0)-(3840,48)，不可见，但没有启用系统自动隐藏（ABM_GETSTATE=0）。旧代码只隐藏任务栏窗口，Shell 仍为它保留原高度；状态栏再通过 AppBar 请求一段自己的高度，形成重复占位。截图中的状态栏仍画在屏幕最上沿，应用最大化却从两段占位之后开始。

V9 在“永久隐藏系统任务栏 + 顶部状态栏开启且占位开启 + 实际任务栏位于同一显示器顶部”时，使用 [ABM_SETSTATE](https://learn.microsoft.com/en-us/windows/win32/shell/abm-setstate) 的自动隐藏状态释放系统任务栏的整段空间，再隐藏其窗口。以实际 Shell 查询位置为准，不依赖设置界面中保存的位置值，也不改变任务栏位置。

[ABM_QUERYPOS](https://learn.microsoft.com/en-us/windows/win32/shell/abm-querypos) 可能保留顶部 1～2 像素触边条。此时状态栏占位的下沿直接对齐“屏幕上沿 + 顶距 + 实际状态栏高度”，不在查询结果上继续多加一段完整高度。若 Shell 暂时仍保留整段旧空间，不叠加第二段，后续节拍重试。特殊第三方任务栏若不接受自动隐藏状态，仍需现场验证自定义高度时的行为。

占位变化通知只标记脏状态，复用原 250 ms 检查；查询/设置失败会清理并重试，接受的矩形没有变化时不重复 SETPOS，避免 Shell 通知回路。Explorer 重启后重新注册状态栏。退出时先注销状态栏占位，并仅在任务栏状态仍等于本程序临时状态时撤回该状态，不覆盖后续外部修改。

未修改底部 Dock 的工作区/避让规则，未修改系统任务栏位置，也未改开机自启任务。Windows 最大化继续遵循系统工作区，没有逐帧或逐个强行移动用户应用窗口。

状态栏检查从 60 项增至 82 项，新增覆盖重复占位、1/2 px 触边条、自定义高度/顶距、跨显示器排除、通知回路、失败重试、全屏释放恢复、关闭注销和任务栏状态撤回。加上窗口/分组 96 项、下载 16 项、动画 26 项、输入法 23 项，共 **243 项通过**。Shell 接口由测试替身模拟，未把这些检查当成用户当前桌面的现场结果；当前运行的 V8 未由本轮自动替换。

同 GCC 16.2.0、原版资源和构建参数下，V8 为 436,736 字节，V9 为 **437,248 字节**，增加 **512 字节**。导入的系统 DLL 仍为 20 个；`.bss` 从 0x1638a0 变为 0x1638c0。没有新增常驻线程、扫描定时器或进程，增加少量占位缓存与 Shell 状态查询；未重新做整进程 CPU/内存长期测量。

后续现场复核：使用者手动换到 V9 后反馈目前工作正常。同机只读查询显示，主屏工作区上沿从先前的 64 个逻辑像素变为 32 个逻辑像素，与当前状态栏高度一致；这补充验证了原场景的重复留白已消除，不代表所有第三方任务栏布局均已覆盖。
