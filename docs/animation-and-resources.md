# 压缩飞入动画与资源测量（2026-11-08）

本文保留 v6 的历史测量。最终候选代码相对当前 main 的补测见 [current-resource-comparison.md](current-resource-comparison.md)。v7 的全屏隐藏条件及最新回归数量见 [status-bar.md](status-bar.md)，未用旧测量冒充 v7 的运行时实测。

本地 v6 保留“压缩飞入 Dock”的路径、缓动曲线和设置中的动画时长。Windows 原生最小化过渡不会以 MiniDock 图标作为飞行目标。

## 当前动画选择

在「设置 → 交互动效 → 动画风格」选择。经典压缩飞入（`MinStyle=0`，默认）和经典图标飞入（`MinStyle=1`）沿用上游的真实窗口动画。流畅压缩（`MinStyle=2`）使用 DWM 预览，HDR 桌面下在恢复交接时尝试使用 HDR 快照。两种经典风格都跳过抓帧预热、合成预览和快照交接。旧配置的 `MinStyle=0/1` 继续使用相应经典风格，试用版的 `HdrSnap` 键已由风格选择取代。

下列数据来自 v6 的历史实现。当前候选的模式切换和资源开销另行验证。

## 改动

旧路径逐帧移动、缩放真实应用窗口，应用可能每帧处理窗口尺寸变化、页面排版和重绘。现在压缩样式（MinStyle=0）优先注册 Windows DWM 缩略图，让私有预览窗口飞入/飞出 Dock。真实应用在最小化开始时最小化，在恢复动画结束时恢复原窗口；动画不启动 EXE，不逐帧缩放或更改应用窗口样式、透明度。

预览注册、尺寸查询或初始属性设置失败时，释放已获得的预览资源并回退到原实现。“图标飞入”淡入淡出样式（MinStyle=1）保留原实现。计时精度只在本轮动画内配对申请/释放，动画结束后注销预览并销毁私有窗口。没有新增常驻线程、扫描定时器或自有全屏位图缓存，也不把真实应用隐藏或 cloak 后等待未来恢复。

DWM 缩略图是系统合成器提供的窗口视图，相关 API 与限制见微软的 [DwmRegisterThumbnail 文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmregisterthumbnail)。受保护内容、特殊渲染窗口、跨权限限制等仍需在实际应用上复核；成功注册不等于所有内容都一定能够显示。不支持的应用仍可能需要关闭该动画。

## 验证

四组确定性回归：窗口/分组 96 项，网站图标下载 16 项，状态栏 47 项，动画 26 项，合计 **185 项通过**。动画检查模拟 DWM 和原窗口状态，验证不逐帧缩放、最小化/恢复/最大化、资源释放及失败回退，不将这些检查当作真实画面的性能数据。

另用真实 DWM 和独立子进程中的私有 Win32 窗口验证，两种路径各运行两次最小化和恢复，共 8 次。为暴露旧路径重排的成本，测试窗口在每次 WM_SIZE 中等待 8 ms。每次飞行动画设为 400 ms，源窗口为工具窗口，不加入用户的 Dock；不操作用户已有应用，不注册全局钩子或修改 Windows 动画设置。

| 指标 | 真实窗口逐帧缩放 | DWM 预览 |
| --- | --- | --- |
| 每次向源窗口发出的缩放请求 | 16～32 | 0 |
| 每次源窗口收到的 WM_SIZE | 13～26 | 1（起止状态切换） |
| 400 ms 内动画帧提交次数 | 16～32 | 66～67 |
| 帧提交间隔 P95，每次测量结果范围 | 18.75～31.33 ms | 6.91～7.50 ms |
| 最终最小化/恢复状态 | 全部正确 | 全部正确 |

这是带有合成排版负载的私有窗口测试，记录的是 API 帧提交间隔，**不是实际显示 FPS，也不能推算所有软件的流畅度提升比例**。DWM/GPU 的消耗没有包含在 Dock 进程 CPU 计数中。该样本中 Dock 动画 CPU 时间有时增加，不能声称动画总系统资源一定下降。旧路径是当前代码中保留的直接缩放回退路径，两边使用相同帧循环；不是对两个完整发布版进行逐帧录像比较。

原始数据见 [animation_benchmark_results.json](../tests/animation_benchmark_results.json)。可选运行 `tests\benchmark-animation.bat` 重做；它会短暂显示自己的测试窗口，约 5～10 秒后关闭，子进程另有 30 秒退出保护。

本机采样时实际运行的仍是 **v4**，不是尚未切换的 v5/v6。20.45 秒日常桌面采样、12 个逻辑处理器：

| 进程 | 整机 CPU 平均占比 | 工作集中位数 | 私有提交中位数 |
| --- | --- | --- | --- |
| v4 主进程 | 0.083% | 148.30 MiB | 76.07 MiB |
| 原有守护进程 | 0% | 11.50 MiB | 3.28 MiB |

主进程 990～994 个句柄、10～11 个线程；守护进程 146 个句柄、1 个线程。样本来自 2026-11-08 15:47，并非严格空闲，也未覆盖持续拖动或长时间动画。工作集包含共享页；私有提交是已提交的进程私有内存，不等同于私有物理驻留内存。上述数值不能直接归因于新增功能。

## 与原版的同配置比较

为避免替换用户正在使用的 Dock，使用隔离的核心绘制/扫描程序，分别包含原版及修改版的生产源码。输入是同一份配置和图标缓存副本：16 个固定槽位、10 个组、256 px 图标缓存、144 DPI，状态栏启用。私有 Dock/状态栏窗口不显示，禁用钩子、自启、守护进程、自动更新、下载和实际工作区占位。定时器由受控循环模拟；每轮 10 秒，执行 2 次扫描、32 次状态栏绘制以及原有磨砂更新。

每个版本两轮；原版/v4/v5 的第二轮倒序运行，v6 随后另测两轮。原版显示 3 个运行图标，修改版开启分组运行功能后显示 7 个。不是完全相同的输出图标数量，符合启用该功能后多显示 4 个图标的情况。

| 版本 | 私有提交中位数 | 相对原版 |
| --- | --- | --- |
| 原版 1.7.4 源码 | 47.18 MiB | 基线 |
| 本地 v4 | 47.71 MiB | +0.53 MiB |
| 本地 v5 | 48.24 MiB | +1.06 MiB |
| 本地 v6 | 48.44 MiB | +1.26 MiB（约 2.67%） |

额外 4 个 256 px 图标的原始像素缓存合计约 1 MiB。关闭分组运行/托盘新增显示的单轮对照：v5 47.17 MiB，v6 46.87 MiB，与原版接近。页驻留、分配器、Shell 缓存和测量时的桌面窗口都会造成波动，不能把各版本中位数差额当作每项补丁固定的内存成本。

整机 CPU 平均占比中位数分别约为原版 0.124%、v4 0.143%、v5 0.130%、v6 0.150%。每轮仅 10 秒、样本数少，不能据此确认存在稳定的 CPU 回归或优化。各轮采样前后的句柄净增量均为 0；工作集受系统回收影响，不用于精确计算功能增量。

这些数值只代表隔离核心工作负载，**不能与上表完整运行 v4 的 148 MiB 工作集直接相减**。也不能代替长时间运行、真实应用动画和 GPU/DWM 的整机性能测试。原始数值见 [resource_comparison_results.json](../tests/resource_comparison_results.json)；不发布用户配置及应用路径。

## EXE 体积

使用相同 w64devkit 2.11.0 / GCC 16.2.0、相同原版资源和现有 `build.bat` 参数重编译：

| 版本 | EXE 大小 |
| --- | --- |
| 原版 1.7.4 源码（3d11ae8） | 427,008 字节 |
| 已合并 PR #10（4f9b6fb） | 432,640 字节 |
| 本地 v4 | 433,152 字节 |
| 本地 v5 | 436,736 字节 |
| 本地 v6 | 437,760 字节 |

本轮动画改动相对 v5 **增加 1,024 字节（1 KiB，约 0.23%）**；v6 相对原版同工具链构建增加 10,752 字节（10.5 KiB，约 2.52%）。v6 仍导入相同的 20 个系统 DLL，`.bss` 仍为 0x1638c0，与 v5 相同。

官方发布 EXE 为 370,688 字节，构建工具链和参数不同，不能把它与本机 437,760 字节的全部差额算作源码改动造成的增长。本次本地试用版另标为 1.7.4-animation.6 / 文件版本 1.7.4.6，未修改开机自启任务，也未替换正在运行的版本。
