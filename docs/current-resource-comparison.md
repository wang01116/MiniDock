同 w64devkit 2.11.0 / GCC 16.2.0、同一原版资源及 `build.bat` 链接参数重新构建：

| 指标 | 上游 main | 候选版本 |

| EXE | 432,640 字节 | 437,248 字节 |
| 导入系统 DLL | 20 个 | 相同的 20 个 |
| PE `.bss` | 0x1638c0 | 0x1638c0 |

EXE 增加 4,608 字节（4.5 KiB，约 1.07%）。额外测试、文档和基准脚本不会编入 EXE。候选生产源码及资源继续使用上游版本号，未上传本地 V4～V9 的独立 EXE。

复用既有扫描、250 ms 全屏/状态栏检查、300 ms 状态栏重绘，不新增常驻线程、进程或周期定时器。飞行动画临时创建一个预览窗口及 DWM 缩略图，结束后释放。焦点输入法状态最多两条 20 ms 超时查询；英文布局跳过 IPC。额外运行图标的原始像素缓存为每个 `4 × cacheSize²` 字节：96 px 为 36 KiB，256 px 为 256 KiB，Dock 绘制表面也可能随图标数增加。

## 隔离绘制与扫描工作负载

运行 `tests/benchmark-resources.py`，对同一配置和图标缓存的临时副本进行测量。程序包含各自版本的生产源码，但不进入 WinMain，不注册全局钩子、AppBar、自启或守护进程，不显示自己的窗口。禁用自动下载/更新、日志和窗口飞行动画。定时器由受控循环替代，每轮约 10 秒，执行 2 次扫描、31～32 次状态栏绘制及磨砂更新。

本机 12 个逻辑处理器；16 个固定槽位、10 个应用组、144 DPI、256 px 图标缓存。上游显示 4 个运行图标，候选启用组内运行图标后显示 7 个。两版各测两轮，第二轮倒序；已有托盘常驻配置在两边都保留。

| 指标（两轮中位数） | 上游 main | 候选版本 | 本次样本差额 |
| --- | --- | --- | --- |
| 私有提交 | 47.36 MiB | 47.77 MiB | +0.41 MiB |
| CPU，占全部 12 个逻辑处理器 | 0.098% | 0.137% | +0.039 个百分点 |
| 采样前后句柄净增长 | 0 | 0 | 0 |

候选多显示 3 个 256 px 图标，单是其原始像素缓存合计 768 KiB；私有提交差额还受分配器、Shell/GDI+ 缓存和采样时的页状态影响，不能拿上述 0.41 MiB 当作固定内存成本。另测关闭新增分组显示的候选单轮对照，保留已有托盘名单，恢复为 4 个运行图标，结果在原始数据中。

该表只代表隔离核心负载，样本少、时长短，不能确认长期 CPU 趋势或代表完整应用的工作集。未覆盖真实 Shell 占位变化、持续动画、所有第三方输入法及 DWM/GPU 开销；动画可能把部分工作转移给系统合成器，不能据此保证整机资源下降。

原始数据：[current_resource_comparison_results.json](../tests/current_resource_comparison_results.json)。测量只输出计数和资源数值，不输出或提交用户配置、图标缓存及应用路径。

## 复现

Windows x64、Python 3.10+、git 和 MinGW-w64 GCC 在 PATH 下：

```powershell
python tests/benchmark-resources.py --profile <包含MiniDock.ini的配置目录> --baseline origin/main --out resource-results.json
```

脚本把配置和 icons 副本放在专用临时目录，不写回原配置；编译和测量结束后清理经过路径校验的临时目录。基线源码取指定 git ref，候选源码取当前工作树。两轮正常对照和一轮关闭新增分组显示的对照共约一分钟。不同桌面运行应用、DPI、配置及输入焦点会改变结果。
